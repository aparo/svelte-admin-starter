# Agent 指令审计（2026-09-06）

范围：仓库 `AGENTS.md`、`CLAUDE.md`、两项 canonical skill 与其 Claude 入口、技能引用和 UI 元数据、页面与发布流程、GitHub CI。全局个人技能及模型运行参数不属于本次仓库修改。

## 官方依据

[GPT-6 Astra 指导](https://developers.openai.com/api/docs/guides/latest-model#prompting-best-practices) 建议审计技能和指令文件，明确自主执行与授权边界、沟通风格、委派条件及适量验证。这次将建议转成项目所需的短规则，避免堆叠通用提示词。是否提升任务成功率与耗时仍需真实任务对照，不能仅凭规则变短保证性能提升。

[Codex AGENTS.md](https://developers.openai.com/codex/guides/agents-md) 描述分层指令加载；[Skills](https://developers.openai.com/codex/skills) 描述按需加载、明确触发范围及聚焦单一任务。因此使用一份共享项目契约和按需引用，保留现有技能自动发现与 UI 元数据。

## 发现与处理

| 发现                                                 | 调整                                                                                                                                                                                        |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 两个客户端契约重复，所有页面修改都要求全量检查       | `AGENTS.md` 统一契约与按风险验证；`CLAUDE.md` 只负责转入                                                                                                                                    |
| 保护路径一律禁止重写，容易阻碍用户已授权的维护       | 保留架构和用户改动约束，移除路径级绝对禁令                                                                                                                                                  |
| 页面入口、工作流和完成清单重复，偏向强制复制模板     | 技能保留决策与引用；模板为可选脚手架，现有页面从当前实现修改                                                                                                                                |
| 版本默认规则自相矛盾，版本请求可能触发完整发布       | 明确版本、tag、完整发布的授权范围；默认 patch，显式目标优先                                                                                                                                 |
| 发布前要求提交或 stash 无关工作                      | 保留无关改动，必要时隔离 checkout                                                                                                                                                           |
| 发布技能与发布文档步骤不同，缺少部分失败后的恢复边界 | 文档维护发布顺序、CI 门槛、notes 文件、不可变 tag 和状态核验；技能按范围路由                                                                                                                |
| CI 与文档重复维护五条验证命令                        | `npm run verify` 成为共同入口，保留全部五项检查                                                                                                                                             |
| 同一分支新提交会重复消耗 CI                          | 按 workflow/ref 取消过时运行，保留缓存与只读权限；依据 [GitHub 并发指导](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency) |
| 技能引用可能受开发文档旧版本表和命令快照误导         | 版本以 package 为准，更新技术栈表和命令说明，引用按需读取                                                                                                                                   |

验证包含技能结构与链接、格式、完整本地 CI 序列，以及本次侧栏样式的可用浏览器检查。GitHub 托管执行需提交后才能核实；本次不发布版本。
